# 03. 워치↔폰 동기화

**무엇을:** 심판은 워치만 차고 경기를 하고, 끝난 경기는 나중에 폰으로 간다. 폰은 프리셋·명단·구독 상태를 워치로 보낸다. Wear OS와 Android 폰 사이에도 Apple Watch↔iPhone과 같은 규칙으로 동작하게 했다.

**왜 이렇게:** 경기장에는 폰이 없거나 블루투스가 끊기는 일이 흔하다. 그래서 워치는 경기를 보관해 두고 폰이 "받았다"고 확인해야 지운다. 확인이 사라지면 워치가 "받았는지" 다시 묻고, 폰은 이미 받은 경기를 두 번 저장하지 않는다. 이 판단은 플랫폼 코드와 떨어진 순수 규칙(`WatchSyncLogic`, `PhoneSyncLogic`)으로 두고 단위 테스트로 고정했다.

**순서:**
1. [design.md](design.md) — Android 폰 앱 설계 중 의도·목표·실패 조건과 동기화·테스트 부분.
2. [plan.md](plan.md) — 동기화 작업 계획.
3. [checklist.md](checklist.md) — 비행기 모드, 앱 강제 종료, 워치 앱 재설치처럼 실제 기기로만 만들 수 있는 상황의 점검 결과.

동기화 규칙 코드는 이 저장소의 `RefereeSession`(Swift)과 `android/session`(Kotlin)에 있다.
